# chore(deps): Python dependency upgrade — 2026-08-26

Branch: `deps/2026-08-26` · Base: `main` @ `9888eab`

## Summary

Routine refresh of the Python dependency set: **38 packages moved**, 8 of them direct. Every gate
that was green before the upgrade is green after, and no application code under `src/` or
`scripts/` changed — the only non-dependency edits are one `ruff` formatter setting and the
toolchain note explaining it.

Nothing was held back. Three bumps were breaking-*shaped* and are each isolated in their own commit
so they can be reverted alone; only one of them cost anything, and what it cost was a config line.

Scope is Python only (`pyproject.toml`, `uv.lock`). `frontend/package.json` is untouched.

## Breaking-shaped changes

### `anthropic` 0.122.0 → 1.0.0 — inert, but named

v1.0 is a real upstream break: the HTTP layer moves from `httpx` to `httpx2`, the legacy Text
Completions API is removed, `temperature`/`top_p`/`top_k` are dropped from Messages, and async
`.with_raw_response` now requires `await response.parse()`.

**None of it reaches this repo.** `anthropic` appears nowhere in `src/` or `scripts/`; the
configured model is `openai:gpt-5.6-luna`. It resolves independently of `pydantic-ai` (2.30 already
permitted 1.0.0), which is why it landed in the routine commit rather than with its apparent
parent.

### `tavily-python` 0.7.27 → 0.8.0 — no wire change

A 0.x minor, so breaking by convention, but the search path gained only two optional parameters:
`language` and `filter_by_language`. `_search` strips `None` values before serialising —
`{k: v for k, v in data.items() if v is not None}` — and `web/client.py` passes neither, so **the
request body on the wire is byte-identical to 0.7.27's**. `search()` still returns an untyped
`dict`, which `client.py` types at the boundary exactly as before.

### `ruff` 0.15.20 → 0.16.4 — one config line

Ruff 0.16 began formatting Python code blocks **inside Markdown** by default. It wanted to reformat
10 files under `docs/` and **zero `.py` files**, collapsing inline comments those code blocks align
on purpose for reading.

`[tool.ruff.format] exclude = ["*.md"]` declines that new surface. Lint is unaffected:
`[tool.ruff.lint]` selects `E/W/F/I/UP/B/C4/SIM` explicitly, so 0.16's jump to 413 default rules
(from 59) does not apply here. `ruff check .` passes with no new diagnostics and no autofixes.

## Decisions made for the reviewer

**Declined ruff's Markdown formatting instead of adopting it.** The alternative — running
`ruff format .` and taking the churn — would have rewritten 10 documentation files to gain
consistency the docs were not asking for. The exclusion holds the gate at *exactly* its prior
scope, and the file counts prove it rather than assert it:

| | Files ruff formats |
| --- | --- |
| 0.15.20 (before) | 86 |
| 0.16.4, no exclusion | 124 |
| 0.16.4, with exclusion | **86** |

It narrows nothing that was ever gated; it declines a surface that was never gated. Recorded in
[`docs/development.md`](../development.md) under *Toolchain facts that have bitten before*, because
the next person to run `ruff format .` will otherwise wonder why `docs/` is untouched.

## Pre-existing issues found (not caused by this PR)

Two, both predating this branch. Neither is addressed here.

### 1. `make scan` is red on `main`

The advisory detector for e-mail addresses fires on
`.claude/skills/upgrade-deps/SKILL.md:297` — the `noreply@anthropic.com` in the example commit
message in §10 — against a baseline of 0. The same line sits at the same offset in
`origin/main`, and this branch adds no e-mail address anywhere, so `scan` has been failing since
`9888eab` (the commit that added that skill) landed.

The fix is a one-line baseline update in `sensitive_baseline.toml`, but that file is a security
baseline and the change belongs to whoever owns it — not folded into a dependency PR.

**Resolved 2026-08-26**, separately from this PR: `scripts/sensitive_baseline.toml` gained an
`[[allow]]` entry for the exact literal `noreply@anthropic.com` — the Co-Authored-By trailer
CLAUDE.md mandates, quoted in commit-message examples. Scoped to that one address, so any other
`@anthropic.com` address still surfaces as drift. `make scan` is green.

### 2. `make smoke-web` is nondeterministic

It failed during verification, so it was run **11 times across both tavily versions** to place the
blame:

| tavily | Passed | Failures seen |
| --- | --- | --- |
| 0.7.27 (old) | 3 / 5 | `streamed_text_matches_done` ×2 |
| 0.8.0 (new) | 2 / 6 | `streamed_text_matches_done` ×2, `web_lane_cited` ×2 |

The dominant failure — streamed text longer than the `done` payload — occurs on **both** versions.
Combined with the byte-identical request body described above, tavily 0.8.0 cannot be the cause.
The agent's lane routing and re-synthesis vary run to run; tool-step counts ranged from 4 to 10 on
the same question.

Not introduced by this PR and deliberately not addressed in it — it is a `src/` behaviour question,
not a dependency one. Worth its own issue.
